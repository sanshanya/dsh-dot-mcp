# 0.9.2 冻档：制品身份与探针（2+2+1 记录）

> 冻结时间：2026-10-27。冻结的是**语义**（下面 §5 的八条），不是实现细节。
> 只要实现与这八条冲突，改实现；要改这八条，重跑本文的 2+2+1。

## 1. 起因（三条实测，不是推测）

| # | 观测 | 证据 |
|---|---|---|
| E1 | `health.bridge.artifact_sha256` 描述的是**磁盘**，不是进程在跑的代码 | 只跑 `node scripts/write-buildmeta.mjs`（不重建、不重启），同一个 pid 的自报值从 `5e2f65aa0f212959` 变成 `b8549883b6388d38` |
| E2 | 同一棵树能产出**三个互不相容的 16 位哈希** | stamp 含 `client.js` = `b854…`；同一方案不含 = `5e2f…`；提议的排序串方案 = `5c4bb275c95eb583` |
| E3 | stamp 从未覆盖过最终产物 | `build` = `build:server`（含打 stamp）`&& build:client`；`lib/client.js` 比 stamp 晚 **192ms** 写盘 |

E2/E3 合起来意味着：任何以 stamp 为准的身份判断，都在描述一个**磁盘上从未同时存在过的树**。

## 2. 两稿（独立，且结论相反）

- **P1（本席预派稿）**：在 `bridge.ts` 模块作用域捕获 `LOADED_META`，health 时重新读 stamp 比对 → `stale`。
- **P2（子代理稿）**：**否决 stamp 基准**。理由：stamp 可以被单独重跑，基准点因此可伪造（E1 就是这么发生的），这是**不动点问题**。改为在模块求值时对 `lib/**/*.js` 做内容快照，运行时按内容比对，**不读任何其它工具会写的文件**。

两稿的冲突点就是要审的点：**基准从哪里来**。

## 3. 两审（对抗，且各自推翻了一部分）

### C1（机制审）
- **BLOCKER**：`stamp_matches_disk` 按规范无法实现——算法与文件集都不同（E2 即证）。
- **BLOCKER**：`relpath\0bytes` 拼接**不是单射**：`[["a","b"],["c","d"]]` 与 `[["a","bc\0d"]]` 序列化相同。
- **BLOCKER**：`changed` 无法从"只有文件名"的快照推出——旧字节已被覆盖。
- **BLOCKER**：P2 的"放在 bridge.ts 最后"**不成立**：静态 import 被提升，位置只排序 bridge 自己的依赖；`lib/index.js` 里 bridge 是第 3 个 import，`mcp.js`/`http.js` 在其后才求值。
- **MAJOR**：一次瞬时扫描错误会把 `unknown` 钉死整个进程生命。
- **MAJOR**：排除 `client.js` 是**朝发布方向**开洞——`build:server` 会删掉它且不重建，而排除后 `current` 照报。
- **MAJOR**：单测里的 `current` 断言**天然成立**（`pretest` 先构建、测试在同进程 import），证明不了任何运行时路径。
- **最致命的一句**：重启会把陈旧洗白，因为基准就取自同一块磁盘。

### C2（价值审）
- **框架错了**：事故是**发布身份**（"我装的是哪个包"），字段量的是**漂移**（"磁盘动过没有"）。干净安装的 0.8.0 tarball → `current`，错误信念原样存活，还多了个机器可信的证人。
- **留着真正的骗子**：`artifact_sha256` 每次读盘（E1）没被删，反而在旁边加第二个哈希。
- **告警疲劳**：开发期 `stale` 长达数小时，布尔值会训练人忽略它。
- **优先级**：先有**第二个宿主**严格优于先有这个字段——`docs/0.9-rollout.md` 里三个 ⏳ 闸门全是因为"跑的还是旧进程"。
- **最强建议**：判决要变成**对声明期望的断言**（`--expect-sha`），而不是自报的状态词。

## 4. 合并：v0 → v1 砍掉了什么

| v0 | 处置 | 理由 |
|---|---|---|
| stamp 基准（P1） | **丢弃** | C1 的不动点论证 + E1 实证 |
| `state` 用自报值当证据（P2） | **保留但降级** | C2：它是"进程与磁盘是否一致"，不是"你装的是哪个版本"；证据由 `--expect-sha` 提供 |
| `relpath\0bytes` 拼接 | **改** | C1 的单射反例 |
| 排除 `client.js` | **改**：纳入 | C1：`build:server` 会删它且不重建 |
| `dsh_health` 带完整证据 | **改**：只带 verdict | C2：远程模型无法处理文件列表 |
| 两个哈希并存 | **改**：一个 | C2 |
| "import 放最后"保证顺序 | **丢弃该主张** | C1：静态 import 提升；改为只声称"lib 目录的启动快照"，不声称"我加载的字节" |
| `stamp_matches_disk` | **保留在 /status，且同源** | 由同一个 `fingerprint()` 生产，才能实现 |

## 5. 冻结的八条语义

1. **一个算法，一处实现**：`src/code-identity.ts` 的 `fingerprint(root)`。stamp 脚本 import 它，运行时不另写一套。
2. **单射原像**：每文件贡献 `relpath\0sha256(bytes)`，以 `\n` 连接；`relpath` 一律 POSIX 分隔。
3. **纳入 `client.js`**：缺它即 `stale`。
4. **绝不抛出**：任何失败变成 `reason`，插件启动不因诊断字段而失败。
5. **`unknown` 优于 `current`**：基线缺失、扫描失败、空树一律 `unknown`。
6. **`artifact_sha256` 的语义改为"本进程启动时捕获的 lib/ 身份"**，并**不再每次读盘**。这是对 0.8 线字段的**破坏性语义变更**，在 CHANGELOG 明写。
7. **证据只在 `/status`**：`changed[]`（≤5）、`changed_total`、`snapshot_at`、`files`、`stamp_matches`。MCP 工具只给 `code.state`。
8. **判决的边界写在工具描述里**：`current` 不表示构建成功、不表示没有半成品构建、不表示 peer 依赖是新的、不表示代码正确。

## 6. 这个字段**不**能证明什么（写进文档，不藏）

- 干净安装的旧包 → `current`（C2 的核心反驳，无解，只能靠 `--expect-sha`）。
- 只改 `src/` 不构建 → `current`（哈希覆盖 `lib/`，不覆盖源码）。
- peer 依赖（`@deepseek-ai/dsh-*`）被换 → 永远看不见。
- 半成品构建期间重启 → 快照等于磁盘，`current`。
- 重启本身会洗白：基准来自同一块磁盘。

因此 `--expect-sha` 是**主**证据，`state` 是**辅**证据。发布时把 sha 与 tarball 一起公布，让外部测试者断言它。
